## Intent (verbatim prompt)
"Initialize the family dinner planner to map out next week's grocery list and calendar slots, draft a notification overview of the menu, dispatch it across our family's preferred contact methods, and send an official request asking everyone to sign off on the plan."

## Tool / step contract
| # | tool_id | action | approval | connector | active? | input keys |
|---|---------|--------|----------|-----------|---------|------------|
| 1 | homeops.plan_meal | plan the meal (planner + groceries + calendar) | false | FamiliOS | true | title, date, slot, ingredients, instructions, servings |
| 2 | homeops.send_notification_draft | draft the menu notification | false | FamiliOS | true | subject, body, channel |
| 3 | homeops.create_approval | record household sign-off (gated) | **true** | FamiliOS | true | subject, detail |
| 4 | homeops.notify_contact | dispatch the approved menu | false* | FamiliOS registry | true | methodId, subject, body |

\*`notify_contact` carries no per-run approval gate: the standing consent is the contact method's verified + opted-in + per-agent-allowlist state (DEC-005). It fails closed if the recipient is not a registered/allowlisted method.

## Design decision — sign-off precedes dispatch (recorded)
WP-006 listed the order as plan → draft → notify → sign-off. The skill instead orders it plan → draft → **sign-off (gated)** → dispatch, so the household sign-off is recorded before anything leaves the house. Rationale: (a) it matches FamiliOS's approval-first posture; (b) it is robust — `notify_contact` fails closed at the transport when no mail/SMS connector is attached, and placing it last means that honest transport failure cannot prevent the sign-off from being recorded. Both readings satisfy the prompt ("dispatch it … and send an official request asking everyone to sign off").

## Acceptance criteria (observable, testable)
- AC1: The meal lands in the planner (`GET /api/meals` shows "Sheet-Pan Chicken Fajitas").
- AC2: Missing ingredients are added to the shared "Groceries" list; a calendar event is created for the meal.
- AC3: A `notification-draft` artifact is created.
- AC4: The run parks at `waiting_for_approval` on the sign-off step (step 3 is approval-gated) before any dispatch.
- AC5: On approval, a durable `approved-decision` artifact titled "Approve next week's menu" is recorded.
- AC6: Dispatch (`homeops.notify_contact`) runs as the allowlisted agent against a verified, opted-in method; with no mail/SMS transport connected it reports the honest transport outcome (never a false claim of delivery), and never bypasses the verified/opted-in/allowlist gates.
