**ACTIVE — built and locally verified.** Backing skill `skl_uc18_memory_scrapbooker` (server/seed.mjs). Runs end-to-end on the local stack with no external connector.

## Intent (verbatim prompt)
"Take the text highlights and photos from our weekend family outing, log it permanently into our internal family journal, and automatically compile those assets into a formatted digital keepsake artifact."

## Tool / step contract
| # | tool_id | action | approval | connector | active? | input keys |
|---|---------|--------|----------|-----------|---------|------------|
| 1 | homeops.write_memory | log highlights to the family journal | false | FamiliOS | true | text, scope, type |
| 2 | homeops.create_artifact | compile a formatted keepsake artifact | false | FamiliOS | true | title, body, kind |

## Acceptance criteria (observable, testable)
- AC1: A memory row is created with scope `family` and the highlight text (retrievable via `GET /api/memory`).
- AC2: An artifact row is created with `kind: "keepsake"` and a title (retrievable via `GET /api/artifacts`).
- AC3: The run completes with both steps `succeeded`; neither step requires approval (both are low-risk internal writes).
- AC4: Empty highlight text is refused by `homeops.write_memory` with the typed `empty_text` guard (see server/internal-functions.mjs and server/test/internal-tools.test.mjs) — the skill never logs an empty memory.

## Test procedure

- Automated: `node --test server/test/usecase-skills.test.mjs` — "UC-18 Digital Memory Scrapbooker" asserts AC1–AC3 against a hermetic server tenant.

## Not-verified / blocked
