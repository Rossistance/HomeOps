## Intent (verbatim prompt)
"When I create a brand new planning page in Notion for an upcoming family trip, look over my active project categories in TickTick and immediately generate a primary task called 'Book Lodging and Travel'."

## Tool / step contract
| # | tool_id | action | approval | connector | active? | input keys |
|---|---------|--------|----------|-----------|---------|------------|
| 1 | notion.createPage | create the linked trip-onboarding entry (e.g. a companion checklist item) tied to the newly created Notion trip planning page | true | Notion | false | parentPageId, title, sourcePageId |
| 2 | ticktick.listProjects | look over active project categories in TickTick to locate the target trip-planning project | false | TickTick | false | workspaceId |
| 3 | ticktick.createTask | generate the primary task "Book Lodging and Travel" in the resolved TickTick project | true | TickTick | false | projectId, title, sourcePageId |

## Acceptance criteria (observable, testable — no bare "works/fast")
- AC1: The webhook trigger fires only on Notion page-created events matching the configured trip-planning page criteria (e.g. the configured parent database/template), not on every Notion page creation.
- AC2: notion.createPage's request is scoped as linked to the triggering page (`parentPageId`/`sourcePageId` set to the newly created page's id), never as an unrelated top-level page.
- AC3: ticktick.createTask's `title` is exactly "Book Lodging and Travel" and its `projectId` resolves to a project that ticktick.listProjects reports as currently active (not archived/completed).
- AC4: ticktick.createTask is invoked at most once per triggering Notion page id (no duplicate onboarding tasks if the webhook re-delivers the same page-created event).
- AC5: If ticktick.listProjects returns no active project matching the configured target, ticktick.createTask is not invoked with an unresolved or blank `projectId`.
