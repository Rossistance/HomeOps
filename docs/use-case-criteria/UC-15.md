## Intent (verbatim prompt)
"Every Sunday night, trigger a web hook to read the latest metrics from our custom family budget tracking endpoint, then securely push an updated data payload back to our external tracking spreadsheet."

## Acceptance criteria (observable, testable — no bare "works/fast")
- AC1: The schedule trigger fires exactly once per week, Sunday night in the configured local timezone.
- AC2: http.get's request targets the configured family-budget-tracking `endpointUrl` exactly, with no hardcoded or placeholder URL substituted.
- AC3: http.post's `payload` is derived from (and field-traceable to) the metrics returned by the preceding http.get call, never a static/fixture payload unrelated to that response.
- AC4: http.post is only invoked after http.get returns a well-formed, successful response (e.g. valid JSON metrics); a failed or malformed GET blocks the POST rather than pushing a partial or empty payload.
- AC5: http.post is invoked at most once per weekly trigger tick (no duplicate pushes to the external spreadsheet on retry/retrigger).
