## Intent (verbatim prompt)
"When a critical family commitment pops up, automatically add a placeholder event directly onto my Microsoft 365 work calendar to block that time off as busy."

## Tool / step contract
| # | tool_id | action | approval | connector | active? | input keys |

| 1 | outlook.createEvent | create a placeholder "busy" event on the MS365 work calendar matching the triggering family commitment's time window | true | MS365 | false | calendarId, title, start, end, sourceEventId |

## Acceptance criteria (observable, testable — no bare "works/fast")
- AC1: outlook.createEvent is invoked only when a qualifying "critical family commitment" event is created in FamiliOS (per the configured trigger filter), not for every calendar event that gets created.
- AC2: The created MS365 placeholder event's `start` and `end` exactly match the triggering family commitment event's start and end times.
- AC3: The placeholder event's title/subject is a generic busy marker (e.g. "Busy" or "Family Commitment") and never carries the original family event's title, notes, or attendee details onto the shared work calendar.
- AC4: The placeholder event's free/busy transparency is set to "busy" (not "free"), so it actually blocks the work-calendar slot.
- AC5: outlook.createEvent is called at most once per triggering `sourceEventId` (no duplicate placeholders if the trigger fires again for the same family event, e.g. on an edit-without-time-change).
