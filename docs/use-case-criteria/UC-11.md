## Intent (verbatim prompt)

## Acceptance criteria (observable, testable — no bare "works/fast")
- AC1: todoist.listTasks' returned set is filtered to "active" (pending, non-completed, non-archived) tasks only.
- AC2: Each returned task retains its original due date and project/list association, so a caller can compute "overdue" (due date earlier than the current date) without an additional lookup.
- AC3: The result set is complete for the configured backlog scope — it is not silently paginated/truncated below the actual active-task count for the seeded backlog.
- AC4: Running the audit twice in immediate succession (no intervening writes) returns a stable, identical set of tasks (no missing or duplicate entries).
- AC5: When there are zero active tasks, todoist.listTasks returns an explicit empty list rather than an error or a null result.
