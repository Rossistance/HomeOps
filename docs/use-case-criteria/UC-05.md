## Intent (verbatim prompt)
"Every Sunday evening, look at all my scheduled entries on my corporate Outlook calendar, cross-reference them with my existing Google calendar events, and copy any new work commitments over to the family calendar so we stay aligned."

## Tool / step contract
| # | tool_id | action | approval | connector | active? | input keys |
|---|---------|--------|----------|-----------|---------|------------|
| 1 | mscal.list | list all scheduled entries on the corporate Outlook (MS365) calendar for the upcoming window | false | MS365 | false | calendarId, startDate, endDate |
| 2 | calendar.list | list existing events on the family Google calendar for the same window | false | MS365 | false | calendarId, startDate, endDate |
| 3 | calendar.create | create a new family-calendar event for each work commitment not already present | true | MS365 | false | calendarId, title, start, end, sourceEventId |

## Acceptance criteria (observable, testable — no bare "works/fast")
- AC1: mscal.list returns all Outlook calendar entries whose start time falls within the configured lookahead window (e.g. next 7 days).
- AC2: calendar.create is only invoked for an Outlook entry when no existing family-calendar event shares the same source event id or an overlapping title+start-time match from calendar.list (de-duplication).
- AC3: Each created family-calendar event's title is traceable back to the source Outlook event (e.g. carries the original title or a `sourceEventId` reference).
- AC4: The schedule trigger fires exactly once per week, Sunday evening in the configured local timezone.
- AC5: Running the sync twice in the same window produces no duplicate family-calendar events (idempotent on `sourceEventId`).
