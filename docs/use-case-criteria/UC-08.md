## Intent (verbatim prompt)
"Check my primary Dropbox folder for newly added family documents. If you don't find a dedicated storage directory named '2026 Medical Records', build a new folder with that name and move the files there."

## Tool / step contract
| # | tool_id | action | approval | connector | active? | input keys |
|---|---------|--------|----------|-----------|---------|------------|
| 1 | dropbox.listFiles | check the primary Dropbox folder for newly added family documents and folders | false | Dropbox | false | folderPath, sinceDate |
| 2 | dropbox.createFolder | build the "2026 Medical Records" folder if it does not already exist | true | Dropbox | false | path, folderName |
| 3 | dropbox.move | move each newly added family document into the "2026 Medical Records" folder | true | Dropbox | false | sourcePath, destinationPath, fileId |

## Acceptance criteria (observable, testable — no bare "works/fast")
- AC1: dropbox.createFolder is only invoked when dropbox.listFiles' folder enumeration shows no existing folder named exactly "2026 Medical Records" (exact-name match, not a fuzzy/partial match to a similarly-named folder).
- AC2: dropbox.move is only called for files identified as newly added (added after the configured last-run/lookback timestamp), never for pre-existing files already in the primary folder.
- AC3: Every dropbox.move call's `destinationPath` resolves to the "2026 Medical Records" folder, whether that folder pre-existed or was just created in step 2.
- AC4: dropbox.createFolder is never invoked more than once per run (no duplicate-folder creation attempts once the folder is confirmed to exist).
- AC5: dropbox.move is invoked at most once per matched `fileId` (no duplicate moves if the same file is seen again on a retriggered run).
