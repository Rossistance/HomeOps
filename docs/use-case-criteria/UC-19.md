## Intent (verbatim prompt)
"Draft a family event for next month's 'Family Reunion Picnic', generate the primary preparation checklist with a line item for 'Pick up ice', assign a designated driver for the event logistics, and assign who is responsible for bringing the side dishes."

## Acceptance criteria (observable, testable)
- AC1: Exactly one event titled "Family Reunion Picnic" is created.
- AC2: Its checklist contains an item "Pick up ice".
- AC3: `driverId` is set to a real household member id (`m-morgan`) on that same event.
- AC4: At least one what-to-bring item is present on that same event.
- AC5: Steps 2–4 all operate on the SAME `eventId` returned by step 1 (the key correctness property). If the id is not threaded, `homeops.update_event_checklist`/`assign_driver` return `event_not_found` and the run fails.

## Notes on eventId threading (design)
- The seeded skill leaves `eventId` empty on steps 2–4; the run engine threads it from step 1's returned `id`. With no AI provider connected (the hermetic case), the engine's deterministic input threading fills an empty required `eventId` from the most recent prior succeeded step whose returned id is an `ev_`-prefixed event id (server/engine.mjs `deterministicFill`). This is narrow by design — it never fills member-reference ids like `driverId`.
